# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability.

Use GitHub's private vulnerability reporting for this repository. Include the affected commit, a clear reproduction path, impact, and any suggested mitigation. Do not test against systems or devices you do not own or have permission to test.

## Scope

Examples include authentication or authorization flaws, cross-tenant data exposure, secrets exposure, injection, XSS, CSRF, SSRF, insecure defaults, and unintended Android device actions.

## Handling

The maintainer will assess reports, coordinate a fix where appropriate, and publish a security advisory after a safe remediation window. Please avoid including credentials, customer data, or device enrollment tokens in the report.
